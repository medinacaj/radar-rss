# Fuentes automáticas

`deploy.yml` programa noticias a las `:17` de cada hora UTC. GitHub puede retrasar o saltar ejecuciones; es una frecuencia prevista, no una garantía. El navegador solo recibe publicaciones generadas por el servidor.

Antes de recopilar noticias, `scripts/source_discovery.py` consulta su estado. Si han transcurrido 48 horas, investiga las once carpetas con búsquedas temáticas de Google News RSS y examina enlaces RSS/Atom declarados en las portadas de los editores encontrados. Cada ciclo rota la primera carpeta y revalida hasta cinco fuentes AUTO anteriores. No usa un modelo de IA, claves ni servicios nuevos.

Las altas deben superar verificaciones reproducibles: HTTPS público, DNS fijado a una IP pública durante TLS, redirecciones dentro del mismo editor, `robots.txt`, límites de descarga, RSS/Atom válido, al menos tres titulares distintos con enlaces originales y fechas recientes, español y pertinencia temática por heurísticas. Para carpetas geográficas, los titulares deben mencionar lugares pertinentes. Solo se permiten el host del editor y su variante `www`; puede descartarse un feed legítimo hospedado en otro dominio. Las ventanas son 45 días y 730 días para investigación. No se crean fechas de publicación, no se verifican hechos y la selección no equivale a una recomendación editorial.

Los límites por ciclo son 180 segundos, 100 solicitudes, 22 candidatos, dos feeds por candidato y cinco altas. El catálogo AUTO nunca supera 100 fuentes; el archivo de estado no supera 250 KB al cargar. Los límites se aplican también a robots y redirecciones; las respuestas individuales no exceden 1 MB (portadas: 256 KB; robots: 64 KB). DNS tiene un máximo de tres segundos. Un watchdog interrumpe el socket al vencer el plazo absoluto, incluyendo conexión TLS, cabeceras y delimitadores de chunks; las lecturas también comprueban el tiempo restante. Se descartan bloqueos y se respeta el intervalo que indique robots sin hacer sondeos alternativos para sortearlo.

El catálogo curado `sources/feeds.opml` conserva sus 443 suscripciones y sus IDs. El OPML efectivo se escribe en `$RUNNER_TEMP/effective-feeds.opml`; únicamente existe durante el build. El colector habitual obtiene ambos tipos de fuente, conservando sus comprobaciones de hosts públicos para cada descarga y redirección. Las fuentes AUTO llevan una marca explícita en el OPML y usan el mismo transporte con IP fijada durante cada ingesta. Las fuentes curadas conservan su transporte e identificadores. Cada AUTO tiene un máximo total de 12 segundos y ocho solicitudes, sin reintentos de 429 ni alternativas que sorteen bloqueos.

`web/data/discovered-sources.json` es público. Incluye URLs, categoría, nombre `AUTO — …`, ID derivado de la URL, fecha de aceptación, fecha de última validación, búsqueda de origen, editor y número de titulares utilizables. `last_checked_at` se actualiza incluso con cero altas o fallos de red, para no repetir la investigación cada hora. `last_scan` conserva éxitos/errores de búsquedas, errores de editores, denegaciones de robots y rechazos de validación. El resultado distingue `unavailable` (ninguna búsqueda disponible), `partial`, `added` y `no_eligible_sources`; no presenta una caída de red como una búsqueda satisfactoria sin novedades. El ensamblador del OPML vuelve a comprobar esquema, dominio, ID, método, categoría, cuota y fechas. Una validación caduca a los 90 días; la rotación completa de 100 fuentes tarda hasta 40 días. Entre revisiones se reutilizan las fuentes aceptadas; los fallos de red/robots no borran una aceptación anterior. Una revalidación que detecte destino inseguro, XML inválido o rendimiento insuficiente retira la fuente AUTO. No se retiran fuentes curadas.

Una cache independiente se restaura al inicio. Si falta o es inválida, se intenta recuperar exclusivamente `discovered-sources.json` de la URL pública configurada del propio Radar, con el mismo transporte seguro, máximo 250 KB y ocho segundos. No se reemplaza una cache válida por una copia publicada más antigua. Un 404 inicial es legítimo; una recuperación indisponible se marca y se reintenta en la siguiente ejecución. El estado se guarda inmediatamente después de investigar, antes de la ingesta; un fallo posterior no pierde la fecha de revisión. El estado se publica junto a los JSON y se incluye en el artefacto de recuperación de 90 días. La recuperación manual copia el estado si existe en ese respaldo; respaldos anteriores siguen siendo compatibles. Si cache y registro publicado están indisponibles, solo se dispone del catálogo curado y se informa la recuperación pendiente. Las fuentes curadas siempre continúan.

Para ajustar búsquedas y términos, revisar `sources/discovery-policy.json` en un PR. Para retirar una fuente AUTO persistida, eliminarla del estado/cache administrado y revisar la política que permitió su alta; no editar el OPML curado para simular una baja. Las auditorías de catálogo, pruebas, validación de JSON y comprobación de Pages siguen siendo obligatorias. El respaldo mantiene un archivo por ejecución mediante `overwrite: true`, también al repetir el build. El nombre del artefacto Pages contiene el intento del build y se pasa como output al deploy, de modo que una repetición solo del deploy reutiliza el artefacto correcto.

Verificación local: pruebas offline con RSS, Atom, HTML y DNS/conexiones simuladas; integración real con el colector y preservación de los 443 IDs. Si existen variables HTTP(S)/ALL_PROXY, el transporte de descubrimiento se declara no disponible antes de DNS o sockets, conserva aceptaciones vigentes y no intenta conexión directa ni modifica el proxy. La disponibilidad de Google y los nuevos editores desde los ejecutores de GitHub queda pendiente de la primera ejecución productiva. No se han sorteado las restricciones de red del entorno local.

Las fuentes son endpoints públicos de editores en jurisdicciones diversas. Acceso público y robots no conceden por sí mismos licencia de reutilización; términos de cada editor y normativa aplicable continúan como riesgo abierto. Se conserva atribución y enlaces, sin incorporar datos de visitantes, secretos ni artículos completos durante el descubrimiento. Véase [la revisión jurídico-tecnológica](ASESOR_LEGAL_TECNOLOGICO.md).

En cada ingesta AUTO se vuelve a validar el XML, el idioma, la pertinencia, las fechas y los dominios públicos de enlaces. Solo se publican entradas que superen esos filtros. Se omiten imágenes y consultas OG de AUTO; un artículo AUTO cacheado que ya no esté validado por la ingesta actual no se republica. Una caída transitoria conserva la aceptación en el registro, aunque no aporte artículos AUTO en ese build. Los RADAR curados de un editor específico también cuentan al evitar duplicados por editor/carpeta; las búsquedas amplias con web Google no bloquean otros editores.
